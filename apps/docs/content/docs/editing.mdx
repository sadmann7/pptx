Editing requires two things: loading the presentation with `readOnly={false}`, and placing `Presentation.Selection` inside `Presentation.Slide`.

```tsx
<Presentation.Root file={file} readOnly={false}>
  <Presentation.Viewport autoFit>
    <Presentation.Slide>
      <Presentation.Selection />
    </Presentation.Slide>
  </Presentation.Viewport>
</Presentation.Root>
```

## Features

- **Move** shapes by dragging them
- **Resize** shapes by dragging their handles (hold Shift on a corner handle to lock the aspect ratio)
- **Rotate** shapes with the handle above the selection (hold Shift to step by 15°)
- **Right-click** a shape to select it before opening a context menu; right-clicking empty canvas clears the selection
- **Snap** to the slide's edges and center and to other shapes while moving or resizing, with guides showing what lined up (see [Snapping](#snapping))
- **Edit text** inline: click a selected shape again, double-click it, or start typing
- **Keyboard**: Tab and Shift+Tab move through the slide's shapes, and screen readers hear what's selected
- **Multi-select** with Shift/Ctrl/Cmd+click, Ctrl/Cmd+A, or by dragging a marquee on the empty canvas
- **Delete** selected shapes with Delete or Backspace
- **Duplicate** the selection with Ctrl/Cmd+D
- **Copy, cut, and paste** shapes with Ctrl/Cmd+C, X, and V, within a deck or between decks on the page; paste an image to insert it
- **Arrange** with Ctrl/Cmd+] and Ctrl/Cmd+[ (one step forward or backward), or with Shift held (to the front or back)
- **Nudge** with the arrow keys (1 px, or 10 px while holding Shift)
- **Undo** and **redo** with Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z (or Ctrl/Cmd+Y)

Undo and redo shortcuts are disabled by default to avoid conflicts with the surrounding app. Enable them with `undoRedoShortcuts` on `Presentation.Selection`:

```tsx
<Presentation.Selection undoRedoShortcuts />
```

When enabled, they are bound on the document rather than the overlay, so they keep working when undo switches slides or when focus moves to a thumbnail after a keyboard reorder. Only keystrokes aimed at the presentation act on the deck: the boundary is `Presentation.Root` when there is one, otherwise the overlay itself. Text fields are always left alone.

For full control, leave `undoRedoShortcuts` disabled and call `store.undo()` and `store.redo()`.

## Snapping

Moving and resizing snap to the slide's edges and center and to the edges and centers of the other shapes. A multi-selection snaps as one block, and a resize snaps only the edges it moves. Hold Alt (Option) while dragging to place a shape freely.

```tsx
// Snap from further away
<Presentation.Selection snapThreshold={10} />

// No snapping
<Presentation.Selection snapping={false} />
```

`snapThreshold` is in screen pixels, so snapping feels the same at every zoom level. It defaults to `6`.

## Styling the overlay

The overlay is built from parts. Without children, `Presentation.Selection` renders all of them with a default look. Compose them to restyle or leave some out:

```tsx
<Presentation.Selection>
  <Presentation.SelectionBox className="ring-1 ring-blue-500 data-[mode=text]:ring-2">
    <Presentation.ResizeHandle className="size-2.5 rounded-full border border-blue-500 bg-white" />
    <Presentation.RotateHandle className="size-3 rounded-full border border-blue-500 bg-white" />
  </Presentation.SelectionBox>
  <Presentation.SnapGuide className="bg-orange-500" />
  <Presentation.Marquee className="border border-blue-500 bg-blue-500/10" />
</Presentation.Selection>
```

Each part is written once and rendered as many times as needed: one outline per selected shape, eight handles per outline, and one guide per line that snapped. The overlay positions them; how they look is up to you. Composed parts are unstyled, so give handles a size.

| Part                        | Rendered                                                        | State                                              | Attributes                                                          |
| --------------------------- | --------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------- |
| `Presentation.SelectionBox` | Once per selected shape                                         | `node`, `mode`, `dragging`, `rotating`, `rotation` | `data-selection-box`, `data-mode`, `data-dragging`, `data-rotating` |
| `Presentation.ResizeHandle` | Eight per outline, inside `SelectionBox`                        | `direction`                                        | `data-resize-grip` (`nw`, `n`, `ne`, ...)                           |
| `Presentation.RotateHandle` | One per outline, inside `SelectionBox`                          | `rotation`, `rotating`                             | `data-rotate-handle`, `data-rotating`                               |
| `Presentation.SnapGuide`    | Once per snapped line while dragging                            | `axis`, `position`                                 | `data-snap-guide` (`x` or `y`)                                      |
| `Presentation.Marquee`      | While dragging across empty canvas, or drawing with a draw tool |                                                    | `data-marquee`, `data-draw` while drawing                           |

Like the other primitives, every part accepts `render`, and `className` and `style` can also be functions of the part's state:

```tsx
// Corner handles only
<Presentation.ResizeHandle
  className={({ direction }) =>
    direction.length === 2 ? "size-2.5 rounded-full border bg-white" : "hidden"
  }
/>
```

On a shape too small to grab between its handles, they sit just outside it, and a flat line shows only its two ends. Resize handles are hidden while dragging; they stay while editing text, as in Google Slides, and pressing one ends the editing. A rotated shape resizes along its own axes. In a multi-selection, every shape scales by the same factors as the one whose handle is dragged, each along its own axes. The rotate handle sits `--presentation-rotate-handle-offset` (`20px`) above the middle of the top edge and turns with the outline; it is hidden while moving or resizing, and on tables and charts. A snap guide is the line itself, centered on where things lined up and `--presentation-snap-guide-width` thick (`1px` by default), so a background color draws it.

### Theming the default look

The default parts read their colors from CSS variables. Set them on `Presentation.Selection` or on any ancestor:

| Variable                              | Default     | Styles                                           |
| ------------------------------------- | ----------- | ------------------------------------------------ |
| `--presentation-selection`            | `#1a73e8`   | Selection outline, resize handles, and marquee   |
| `--presentation-snap-guide`           | `#f43f5e`   | Snap guides                                      |
| `--presentation-snap-guide-width`     | `1px`       | Snap guide thickness                             |
| `--presentation-rotate-handle-offset` | `20px`      | Distance of the rotate handle above the outline  |
| `--presentation-rotate-cursor`        | `crosshair` | Cursor over the rotate handle and while rotating |

```css
.editor {
  --presentation-selection: var(--ring);
  --presentation-snap-guide: #f97316;
}
```

Inline styles only override the properties they set, so CSS that targets a part's attributes can add anything else (shadows, opacity, transitions) without `!important`:

```css
[data-snap-guide] {
  box-shadow: 0 0 4px var(--presentation-snap-guide);
}
```

## Edit callbacks

Each edit callback receives `(status, error?)` for undo/redo (where `status` is `"success" | "empty"`) and `(nodeId, error?)` for node events. Check `error` to show a toast or log failures:

```tsx
<Presentation.Selection
  onUndo={(status) => {
    if (status === "empty") toast.error("Nothing to undo");
  }}
  onRedo={(status, error) => {
    if (error) toast.error(error instanceof Error ? error.message : "Redo failed");
    else if (status === "empty") toast.error("Nothing to redo");
  }}
  onNodeTransform={(nodeId, error) => {
    if (error) toast.error("Could not move shape");
  }}
  onNodeDelete={(nodeId, error) => {
    if (error) toast.error("Could not delete shape");
  }}
  onTextChange={(nodeId, error) => {
    if (error) toast.error("Text edit failed");
  }}
/>
```

## Programmatic edits

Use `store.edit()` to apply changes from outside the UI (for example, from a toolbar button). Edit operations have full undo/redo support.

```tsx
import { copyNodes, useCreatePresentationStore } from "@diceui/pptx";

const store = useCreatePresentationStore();

// Change a shape's fill color
await store.edit({
  type: "setSolidFill",
  slideId,
  nodeId,
  color: "#ef4444",
});

// Move a shape (slide pixels at 96 DPI)
await store.edit({
  type: "setNodeTransform",
  slideId,
  nodeId,
  position: { x: 100, y: 200 },
  size: { w: 400, h: 300 },
});

// Edit text
await store.edit({
  type: "setTextBody",
  slideId,
  nodeId,
  paragraphs: [
    {
      sourceParagraphIndex: 0, // copy this paragraph's formatting; -1 for none
      runs: [{ text: "Hello world" }],
    },
  ],
});

// Format text: the whole text body, or a range of it
await store.edit({
  type: "setTextStyle",
  slideId,
  nodeId,
  style: { bold: true, color: "#2563eb", fontFamily: "Arial", fontSize: 24 },
  range: { start: { paragraphIndex: 0, offset: 0 }, end: { paragraphIndex: 0, offset: 5 } },
});

// Align paragraphs
await store.edit({ type: "setParagraphStyle", slideId, nodeId, style: { align: "center" } });

// Add a slide from a layout (defaults to the layout of `afterSlideId`)
const { createdSlideId } = await store.edit({ type: "addSlide", afterSlideId: slideId });

// Set or clear (`null`) a slide's own background
await store.edit({ type: "setSlideBackground", slideId, color: "#f8fafc" });

// Duplicate a shape (offset 10px by default) and change the stacking order
const { createdNodeIds } = await store.edit({ type: "duplicateNode", slideId, nodeId });
await store.edit({ type: "reorderNode", slideId, nodeId, order: "front" }); // or "back", "forward", "backward"

// Insert an image: its own size scaled to fit, centered, unless you pass `size` and `position`
await store.edit({
  type: "addImage",
  slideId,
  data: new Uint8Array(await file.arrayBuffer()),
  contentType: file.type, // "image/png", "image/jpeg", or "image/gif"
  name: file.name,
});

// Add a text box (centered and empty by default)
await store.edit({ type: "addTextBox", slideId, text: "Hello" });

// Add a preset shape ("rect", "ellipse", "rightArrow", …), styled from the theme like PowerPoint's
await store.edit({ type: "addShape", slideId, geometry: "roundRect" });

// Set a shape's or picture's outline (width in points); `color: null` removes it
await store.edit({ type: "setOutline", slideId, nodeId, color: "#0f172a", width: 1.5 });

// Copy shapes out of one deck and paste them into another (or the same one)
const clipboard = await copyNodes(sourceDeck, sourceSlideId, nodeIds);
await targetStore.edit({ type: "pasteNodes", slideId: targetSlideId, clipboard });
```

`copyNodes` takes the images the shapes use along with them, and paste reuses any that the deck already has. Shapes that refer to other parts, such as charts, diagrams, and video, are left out and listed in `clipboard.omittedNodeIds`.

In `setTextStyle`, omitted fields are left alone and `null` removes the text's own value so it inherits from the layout again. Text ranges count characters in each paragraph's text, with a line break as one character, and `end` is exclusive.

Edits that create nodes (`addTextBox`, `addShape`, `addImage`, `duplicateNode`, and `pasteNodes`) return their ids in `createdNodeIds`.

`presentation.layouts` maps each layout's part path to its data, including its `name`, for a "new slide from layout" picker.

## Formatting toolbar

`useSelection` gives a toolbar the overlay's selection and formatting commands that work in both modes. While text is being edited they format the selected text, or the word at the caret. Otherwise they format all the text in the selected shapes.

Pressing a toolbar would normally count as a press outside the slide, which clears the selection and ends text editing. Mark the toolbar with `data-pptx-keep-selection` (exported as `KEEP_SELECTION_ATTRIBUTE`) to prevent that. Mark the content of its popovers and menus as well, since they usually render in a portal outside the toolbar. Undo shortcuts pressed inside marked UI apply to the deck.

```tsx
import { useSelection } from "@diceui/pptx";

function FormattingToolbar() {
  const { textStyle, setTextStyle, setParagraphStyle } = useSelection();

  return (
    <div data-pptx-keep-selection="">
      <button
        aria-pressed={textStyle?.bold ?? false}
        disabled={!textStyle}
        onClick={() => void setTextStyle({ bold: !textStyle?.bold })}
      >
        Bold
      </button>
      <button disabled={!textStyle} onClick={() => void setParagraphStyle({ align: "center" })}>
        Center
      </button>
    </div>
  );
}
```

`textStyle` describes the text under the caret or selection: `bold`, `italic`, `underline`, and `strikethrough` are on only when all of it has them, and `color`, `fontFamily`, `fontSize`, and `align` are `null` when it is mixed. It is `null` when nothing with text is selected. The hook also returns `mode`, `nodeIds`, `nodes`, `select(nodeIds)`, `clear()`, `duplicate()`, `remove()`, and `reorder(order)` for the selected shapes, `editText(nodeId)` to start editing a shape's text, `insertTextBox(options?)`, which adds a text box to the current slide and starts editing it, and `insertShape(geometry, options?)`, which adds a preset shape and selects it, so typing starts its text. To let people place them instead, like Google Slides, `startDrawing({ type: "textBox" })` or `startDrawing({ type: "shape", geometry })` arms a draw tool: the slide shows a crosshair, a click places the text box or shape at its default size, and a drag draws it to size (Shift keeps it square). `drawTool` reports the armed tool, and Escape or `startDrawing(null)` disarms it. A text box left empty is removed once editing moves elsewhere.

For a font picker, `getPresentationFonts(presentation)` lists the theme's heading and body fonts, the fonts embedded in the file, and the other fonts the deck's text uses. For a shape picker, `getPresetShapePath(geometry, width, height)` returns SVG path data to draw each preset's preview.

Formatting while text is being edited commits the pending typing in the same edit, so the two undo together. The caret or selection comes back afterwards, and focus returns to the text unless the toolbar is typing into a field of its own, such as a font size box.

## Batch operations

Group multiple edits into a single undoable step with `"batch"`:

```tsx
await store.edit({
  type: "batch",
  operations: [
    { type: "deleteNode", slideId, nodeId: "2" },
    { type: "deleteNode", slideId, nodeId: "3" },
  ],
});
```

## Saving

Call `store.save()` to get the edited presentation as a `Uint8Array`, then trigger a download:

```tsx
async function onSave() {
  const bytes = await store.save();
  const blob = new Blob([bytes], {
    type: "application/vnd.openxmlformats-officedocument.presentationml.presentation",
  });
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = "edited.pptx";
  a.click();
  URL.revokeObjectURL(url);
}
```

The saved file round-trips all untouched parts byte-for-byte. Only slides that were edited are re-serialized.

## Undo / redo stack

The store maintains a linear undo/redo history:

```tsx
store.canUndo(); // true if there is something to undo
store.canRedo(); // true if there is something to redo
store.undo(); // reverts the last edit; navigates to the affected slide
store.redo(); // re-applies the last undone edit
```

Cross-slide edits navigate to the affected slide automatically on undo/redo.

## Reordering slides

Moving a slide is an edit like any other, so it is undoable and included in `isDirty`. The thumbnail strip deliberately ships no drag-and-drop: reordering is left to whatever sortable library you already use, and `Presentation.ThumbnailItem` is built to be wrapped by one. It forwards `ref`, merges arbitrary props and event handlers, and lets your `style` win over its internals so transforms animate normally.

Commit the drop as a `moveSlide` edit:

```tsx
async function onDragEnd({ active, over }: DragEndEvent) {
  if (!over || active.id === over.id) return;
  const toIndex = slideIds.indexOf(String(over.id));
  await store.edit({ type: "moveSlide", slideId: String(active.id), toIndex });
}
```

A few things are worth knowing when wiring this up:

- dnd-kit's `attributes` set `role="button"` and `tabIndex={0}`. Both would override what the list needs, replacing the `option` role and putting every thumbnail in the tab order instead of the single roving tab stop. Drop those two keys and spread the rest.
- Give the pointer sensor a small activation distance (`{ distance: 4 }`), or a plain click starts a drag instead of selecting the slide.
- `store.edit()` is async, so hold the dropped order in local state until it settles; otherwise the strip snaps back to the old order for a frame.
- Clamp the drag with `restrictToFirstScrollableAncestor`. The strip scrolls vertically, and a transformed child still counts toward its scroll container's overflow, so an unclamped drag past the last thumbnail grows `scrollHeight`, which lets auto-scroll run, which grows the transform again — the list scrolls for as long as you hold the pointer at the edge.
- Give a drag overlay's thumbnail the `decorative` prop. The overlay is a second copy of a slide that is still in the list, and without it the copy takes the original's place in the roving focus map, unregisters it on drop, and the deck is announced with a duplicate option.

```tsx
<DragOverlay>
  {draggedId ? (
    <Presentation.ThumbnailItem decorative slideId={draggedId}>
      <Presentation.ThumbnailItemNumber />
      <Presentation.ThumbnailItemPreview />
    </Presentation.ThumbnailItem>
  ) : null}
</DragOverlay>
```

Render the overlay inside `Presentation.ThumbnailList` so the copy can reach the list context it needs to paint a real miniature. It is fixed-positioned, so the strip's overflow will not clip it.

The list also owns ↑/↓/Home/End for roving focus, so a keyboard drag sensor bound to those keys will fight it. Modifier combinations (Alt/Option+↑, for example) pass through untouched.

The demo at the top of this page wires all of that up with [dnd-kit](https://dndkit.com), though nothing in the approach is specific to it. See `SortableThumbnailList` in [presentation-editor.tsx](https://github.com/sadmann7/pptx/blob/main/apps/docs/src/components/presentation-editor.tsx).

## Unsaved changes

`store.isDirty()` reports whether the presentation has changed since it was last saved. If the user undoes those changes and returns to the saved state, it becomes false again avoiding unnecessary unsaved changes warnings.

```tsx
window.addEventListener("beforeunload", (event) => {
  if (store.isDirty()) event.preventDefault();
});
```

In the component tree, use `useHistory`:

```tsx
function Toolbar() {
  const store = usePresentationStore();
  const { canUndo, canRedo, isDirty, undo, redo } = useHistory();

  return (
    <>
      <button disabled={!canUndo} onClick={undo}>
        Undo
      </button>
      <button disabled={!canRedo} onClick={() => void redo()}>
        Redo
      </button>
      <button onClick={() => void store.save()}>{isDirty ? "Save" : "Saved"}</button>
    </>
  );
}
```

Outside the tree, the same values come through `onHistoryChange`:

```tsx
<Presentation.Root
  file={file}
  readOnly={false}
  onHistoryChange={({ canUndo, canRedo, isDirty }) => {
    setHasUnsavedChanges(isDirty);
  }}
/>
```
